Overview & Platform Architecture

TBSH Compliance Audit Logger Pro is a complete Governance, Risk, Compliance (GRC), Operational Resilience, and Evidence Management platform. It captures cryptographic, tamper-evident trails of site activity and establishes secure evidence vaults connected to remote cloud storage providers.

The platform features a modern React-based admin portal powered by the WordPress REST API. It is designed to satisfy major security control audits including:

  • ISO/IEC 27001 (Annex A.12.4.1 logging & A.12.4.2 tamper protection)
  • SOC 2 Trust Services Criteria (Logical access CC6.1 & change management CC8.1)
  • DORA Directive (Incident logging, reporting, and critical ICT vendor governance)
  • NIS 2 Directive (Organizational risk-management, verification controls, and evidence logs)

This documentation contains details about all feature architectures, DB structures, cron mechanisms, setup instructions, and available settings.

Installation & Standalone Architecture

The Pro plugin is architected to run as a 100% standalone premium plugin. It has no dependency on the Free sibling plugin, and does not conflict if the Free plugin is installed or deactivated.

Autoloader Redirection: Upon boot, the Pro plugin registers a dual-autoloader. If the Free version is not active, it dynamically redirects classes in the namespace TBSHComplianceAuditLogger\* to point to its local copy inside includes/Free/. This ensures all database schemas, REST endpoints, and tracking modules bootstrap automatically.

How, Where, and When Things Boot:

  • Autoloading: Triggered on the plugins_loaded hook at priority 5 (before standard plugins load). Class files are parsed from includes/ and includes/Free/.
  • Constants Definition: If the Free plugin is inactive, the Pro plugin defines fallback constants (TBSH_CAL_PATH, TBSH_CAL_URL, TBSH_CAL_VERSION) pointing to its internal directories, so that core assets load seamlessly.
  • Cron Schedules: Registers a daily hook tbsh_cal_cron_job. When triggered, it captures compliance snapshots and runs log retention cleanup according to the configured retention policies.

Continuous Event Logging

The logging engine monitors active events across the site using WordPress hooks. It captures:

  • Authentication Failures: Captures invalid logins via wp_login_failed.
  • User Audits: Logged on user creation, user deletions, role upgrades, and profile changes.
  • Operational Changes: Listens to plugin activation, deactivations, theme swaps, widget modifications, and general settings adjustments.

GDPR IP Anonymization: IP addresses are handled according to privacy controls. If IP masking is enabled, the IP is combined with a site-specific salt and converted using HMAC-SHA-256 to generate a cryptographically secure pseudonym.

Tamper-Evident Hashing Chain

To ensure logs are not altered directly in MySQL by an unauthorized database admin, the logger maintains a cryptographic hash chain: 

Current Row Hash = SHA256( UUID + Timestamp + Message + Actor + Previous Row Hash )

If any row is modified, or if rows are deleted, the chain breaks. The Integrity Center runs a check that recalculates hashes starting from row 1. If any hash mismatch is found, it immediately reports a security warning, pointing out the exact row ID where the modification occurred.

Incident Center & AI Heuristics Pro

When critical security events trigger (e.g. file integrity violations, anomalous database modifications, or brute force attempts), the plugin opens an incident log.

Setup and Workflow details:

  • Manual Logs: Administrators can log custom security incidents using the dashboard layout.
  • AI Analysis: Integrates with OpenAI or Anthropic models. Clicking Analyze Incident sends the incident metadata and surrounding logs to the AI provider, returning an automated summary of the incident's compliance impact and specific recommendations.
  • AI Provider Fallbacks: If the settings do not contain API keys, the AI system runs a local heuristic analysis engine to provide simulated compliance summaries and remediation steps.

5x5 Risk Heat Map Register Pro

Provides a structured risk register aligned with ISO 27001 requirements. Users specify:

  1. Likelihood (1 to 5): Rare, Unlikely, Moderate, Likely, Almost Certain.
  2. Impact (1 to 5): Insignificant, Minor, Moderate, Major, Critical.

The matrix calculates the combined rating coordinate (Low, Medium, High, Critical) and renders them dynamically inside the interactive dashboard heat map. Overdue risk reviews automatically display alerting colors in the grid.

Vendor Governance & Dependency Scanning Pro

Addresses DORA (Article 28) third-party risk management:

  • Partner Profiling: Track contact info, cloud types, data access scopes (None, Read, Write), and DORA Criticality.
  • Supply Chain Scan: Automatically scans the active plugins directories, active themes, and outward webhook structures to identify high-privilege plugins and connected external domains.

Evidence Vaults & Cloud Syncing

System snapshots compile critical server state information into signed JSON files. The snapshot captures:

  • Active WordPress plugins list & version mapping.
  • Administrator user metadata and security keys.
  • Log integrity chain signatures.

Remote Syncing Integrations: Snapshots can be automatically synced to Amazon S3, Google Cloud, Azure Blob, Dropbox, or custom FTP servers.

Cron Automatic Snapshotting: Enable "Automated Snapshots" in settings. A cron event runs daily to compile this evidence and upload it to your remote storage folder.

Compliance Reporting Engine Pro

Allows compiling audit-ready compliance documentation reports in PDF, CSV, or HTML format. Report templates include:

  • ISO 27001 Annex A.12 Audit Pack: Systems logging, database chain verification history.
  • SOC 2 Trust Criteria Report: Logins history, configuration change tracking.
  • DORA Resilience Report: Third-party vendor directory, logged incident records.
  • NIS 2 Audit Pack: Comprehensive compliance readiness checklists, risk assessment scores.

Settings Module Details

Below is a complete description of all configuration settings available in the Pro Settings panel:

Core Settings:

  • enable_logging: Boolean. Enables or disables the central activity logging engine.
  • anonymize_ips: Boolean. If enabled, client IP addresses are obfuscated using HMAC-SHA-256 before insertion.
  • log_retention_days: Integer. Number of days to retain logs in the database. Older records are automatically cleaned by the daily cron task.

Automated Evidence Vaults:

  • auto_evidence: Boolean. If active, the system triggers automated snapshots of system states daily.
  • evidence_retention_days: Integer. Defines how long snapshot files are stored locally before being deleted.
  • remote_sync_provider: String. Choice of none, s3, gcs, azure, dropbox, or ftp.

Remote Storage Credentials:

  • AWS S3: Access Key, Secret Key, Bucket Name, and Region.
  • Google Cloud Storage: Google Service Account JSON payload, Bucket Name.
  • Azure Blob: Connection String, Container Name.
  • Dropbox: API App Access Token, Folder Path.
  • FTP: Host, Port, Username, Password, and Remote Path.

AI Analysis Diagnostics:

  • ai_provider: Choice of none, openai, anthropic, or mock.
  • ai_api_key: String. The secure API key for the selected AI provider.
  • ai_model: String. Override model parameter (e.g. gpt-4o, claude-3-5-sonnet).

Troubleshooting & FAQs

1. The dashboard reports an "Integrity Warning" or "Compromised Chain". What should I do?

This indicates that either a log record was edited or deleted directly, or a custom query bypassed the hashing chain mechanism. You should:

  1. Navigate to the **Integrity Center** and click **Run Validation Scan** to trace the exact mismatch.
  2. Verify if any server management tools edited tables.
  3. Review active login activities around the time of the break.

2. Daily automatic vault snapshots are not being captured.

The system relies on WordPress Cron. If your site has low traffic, WordPress cron events may run late. Consider setting up a real system cron job on your host to query wp-cron.php every 10 minutes: 

*/10 * * * * wget -q -O - http://yourdomain.com/wp-cron.php?doing_wp_cron >/dev/null 2>&1

3. Remote synchronization to S3 or GCP returns "Connection Error".

Ensure your credentials do not have any leading or trailing spaces. If you are using Amazon S3, verify that the IAM user policy has s3:PutObject and s3:ListBucket permissions allowed on the target bucket.
